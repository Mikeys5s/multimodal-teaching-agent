> **本文不是"要不要改页面"，而是"三件东西的叙事要对齐"**

## 二、核心论点：**三件交付物是同一条叙事的三种时间尺度**

| 交付物 | 评委**在哪看** | **看多久** | 谁在动 |
|---|---|---|---|
| **海报** 60×80 | 走过展位时 | **3 秒** | 没人动 |
| **5 分钟演讲 PPT** | 坐在下面 | **5 分钟** | 你动 |
| **Web Demo** | 自己点 | **1–10 分钟，可反复** | 评委动 |
| 作品介绍 PPT | 会后翻 | 按需 | 没人动 |

**⇒ 三者最容易脱节的是 Web Demo** —— 因为**"做出来"不等于"能按演讲的节奏点出来"**。

---

## 三、我列的具体差异（**六条，每条带"要不要动"**）

### ① 默认落地页 —— **要动**

**现状**：打开 URL 落在首页（515 字符的 SPA 壳）。

**差异**：**演讲第 1 页讲痛点、第 3 页讲创新点** —— 而评委自己打开时，
**第一屏看到什么决定他会不会继续点。**

**建议**：**保持首页**，但**首页顶部加一句「这是什么 + 从哪开始看」**。
**⚠️ 不要**为了演讲把默认页改掉 —— 因为**评委是独立访问的，不是跟着你的节奏**。

### ② 页面顺序 vs 演讲顺序 —— **不建议动**

**演讲顺序**（我拟的 5 页）：痛点 → 创新点 → 答疑 → 诚实性
**现有路由顺序**：首页 / 图谱 / 路径 / 答疑 / 复核 / 报告

**⚠️ 它们本来就不必一致** —— **演讲是"讲一条线"，Demo 是"逛一个空间"。**
**强行对齐反而会让 Demo 变得像 PPT。**
**⇒ 建议**：**改成"首页给一条推荐路径"**（下面 ③）。

### ③ ⭐ 最关键的一条：**Demo 需要一个「演示路径」入口**

**问题**：Demo 有 629 个点、28 个端点，**评委不知道该点哪个**。

**⇒ 建议做一件事**：**首页放 3–4 个"从这看起"的入口**，每个对应演讲里的一镜：

```
[ 看依赖图与学习路径 ] → /path 打开拥塞控制的 4 步链
[ 看多轮答疑怎么降级 ] → /tutor 打开（或预置）一个会话
[ 看我们怎么处理重复数据 ] → /graph 定位到那组 35 个成员的点
[ 看校验体系 ]          → /report（40 项复验 + 6 项自检的结果）
```

**⇒ 这样每一镜都能独立成立，不依赖讲解。**

**⚠️ 这件事**只有 P3 能落**（前端），但**内容我来定**（因为我知道演讲讲什么）。

### ④ "演示模式" —— **要，但用最轻的方式**

**问题**：演讲时**不希望**出现"上传中/等待/报错"。

**⚠️ 但做"演示模式"是**真改代码**（回归风险）。**

**⇒ 我的建议**：**不做演示模式，而是"提前准备好状态"**：

| 演讲要演的 | 怎么准备（**不改代码**） |
|---|---|
| 上传 → 解析 | **材料已入库**（4 份在位）⇒ **跳过上传环节**，从"已解析"讲起 |
| 多轮答疑降级 | **演讲前 10 分钟开一个会话，问 2 次** ⇒ 讲的时候接着问第 3 次直接看降级 |
| 学习路径 | **材料已在** ⇒ 打开即有 |

**⇒ 这比做"演示模式"便宜得多，而且不冒险。**

### ⑤ ⭐ 我探到一个**硬约束**：**没有"预置演示数据"的入口**

我查了 28 个端点，**没有 `demo` / `seed` / `sample` 这类入口**。

**⇒ 后果**：**演讲里最亮的那一镜（四轮降级）要现场真的问 4 次**，
而**每轮约 10–20 秒**（要等模型）⇒ **5 分钟里要占 1 分钟以上**。

**⚠️ 这条要算进演讲的时间预算**：

```
5 分钟 = 300 秒
  封面 + 定位        20s
  设计思路与分工      50s
  遇到的问题         70s
  成果（含演示）     120s   ← 四轮答疑 + 路径各占一半
  收尾               40s
```

**⇒ 建议**：**演示只演"第 3 轮降级"那一镜**（**前面两轮口述带过**），
把 4 轮压缩成"第 1 轮口述 → 直接问第 3 轮 → 看降级"。
**⚠️ 但这样就是"跳轮"** —— **要不要这么演，你定**（**我建议真跑，因为评委看得出真假**）。

### ⑥ 海报上的 URL —— **要注意第一屏**

海报印的是**同一个 URL**。**评委扫码/输入后看到的第一屏**要能自解释。

**⇒ 和 ③ 是同一件事**：**首页给了"从这看起"，海报就不用印解释文字。**

## 四、汇总：**要动的 / 不要动的**

| # | 事项 | 动不动 | 谁 |
|---|---|---|---|
| ① | 默认落地页 | **不动**（保持首页） | —— |
| ② | 页面顺序对齐演讲 | **不动**（强行对齐会变味） | —— |
| ③ | **首页加 3–4 个「从这看起」入口** | **✅ 要动**（**收益最大**） | **内容 P2 定 / 落地 P3** |
| ④ | 演示模式 | **不做**（改代码有风险）→ **改成"提前准备状态"** | P3（演讲前准备） |
| ⑤ | 预置演示数据入口 | **不加**（但**演讲时间预算要因此调整**） | —— |
| ⑥ | 海报 URL 的第一屏 | 同 ③ | —— |

## 五、要你拍板的三件

1. **P1 的 Ch03 例题怎么办**（**做 / 卸 / 转**）—— **这条不定他没法干活**
2. **③「从这看起」入口做不做** —— 我判断**收益最大**，但要占 P3 的时间（约 30 分钟）
3. **⑤ 演讲里四轮答疑：真跑 4 轮（占 1 分钟）还是只演第 3 轮** ——
   **我建议真跑**（评委看得出真假），**但那要砍别的时间**
