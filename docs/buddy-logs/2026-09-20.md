## 一、本日 LearnBuddy 解决的核心问题（按价值排序）

### 1. 同步 P1/P2 的工作 —— 并顺带发现"本地 git 全在骗人"

| 问题 | 怎么发现 | 结论 |
|---|---|---|
| 本地 `origin/main` 停在 `85975e8`，远端已到 `730b12fc`（**领先 103 个提交**） | `ls-remote` 与 `rev-parse` 交叉验证 | 本地视图**过期整整一天**，此前所有"远端状态"判断都基于旧值 |
| `git fetch` 的 stderr **明确打印成功**，但 `rev-parse` 仍返回旧值 | 拿 `ls-remote` 当真值逐条比对 | **fetch 自己的输出也不能信** |
| 另外：`refs/heads/main` 是**松散文件**（旧值），优先级高于 `packed-refs` | 逐个 ref 检查松散/打包分布 | 只改 `packed-refs` **完全不生效**，必须一并覆盖松散文件 |

**产出**：`p3_refs_fix.py`（refs 体检 + 修复，`inspect`/`apply` 双模式）；同步完成后分支落后 main **0** 提交。

### 2. 三份材料的"对照判据" —— 以及它差点给出假绿

用三份开放教材（Ch03/Ch05/Ch06）当对照组，检验"某份数据是不是 mock"。

**⚠️ 关键发现**：`/materials/{id}/outline` 的**整响应 sha 三份不同**，看着像"三份不同"；但**剥掉回显字段 `material_id` 之后，三份完全相同**。
→ **判据算法必须写死：先剥回显字段再比。**
（"三份一样 = 假数据"这个判据本身没错，**错的是实现它的那个比法**。这是 #58 模式 B 的一个新变种：检查方法自己制造了差异。）

### 3. 答疑链路 mock 的**取证**（演示红线）

光说"这是 mock"不够，因为四个端点全部 200、SSE 事件序列也正确。**外形合格**，所以要用硬证据：

| 证据 | 做法 | 结果 |
|---|---|---|
| 会话 ID 固定 | 用**不同** `student_label` + `material_scope` 建两次 | 两次都返回 `qs_9f2a1c40_001` |
| 引用的知识点不存在 | 拿 `state.current_kp_id` 去查库 | **HTTP 404「知识点不存在」** |
| 忽略问题内容 | 两个**主题完全不同**的问题，比对 SSE 原始字节 | **逐字节相同**（sha1 `1c472f894a`） |
| 内容穿帮 | 读回答正文 | 「如果数组已经是升序的，**快排**还需要比较多少次？」 |

**方法学**：证"某功能是假的"时，**不要只看状态码和事件序列** —— 那恰好是 mock 最容易做对的部分。
