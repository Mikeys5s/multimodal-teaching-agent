## 一、本日 LearnBuddy 解决的核心问题（按价值排序）

### 1. 先纠了一个前提错误：**"工作仓库"到底是哪一个**

**问题**：`Desktop\aicoding` 与 `Desktop\xizhi` 两个目录同时存在，文档与脚本在两边都有。若在错的那边干活，等于白做。

**怎么发现**：不靠记忆，直接看目录结构——`xizhi` 有 `backend/` `frontend/` `docs/` `scripts/` `Dockerfile` `docker-compose.yml`；`aicoding` 只有文档与旧克隆。

**结论**：**真正的工作仓库是 `Desktop\xizhi`**；`aicoding` 只用于文档暂存与产物导出。此后所有 git 操作都在 `xizhi`。

> 这条现在看很基础，但**当时两边都"像"**——而且我在 `aicoding` 里已经写了几份报告。

### 2. 补齐 `frontend` 缺失依赖 —— 而 npm 走不通，只能绕过

**问题**：`vite dev` / `vite build` 报缺 `@babel/parser`、`json5`（`@babel/core` 的依赖）；`node_modules` 里还有 npm 中断安装留下的暂存目录（`.autoprefixer-*`、`.sucrase-*`）。

**怎么发现**：从报错反查到具体包与版本，再逐个比对 `node_modules` 里已有的版本（`@babel/*` 是 7.29.7/7.29.8，兼容）。

**结论**：**`npm install` 被本机的"删除守卫"拦住走不通** → 改用 **node `fetch` 下载 tarball + `tar -xzf` 解压进 `node_modules`**。
验证方式不是"看着像好了"，而是：**新起一个 dev server（端口 5199），`GET /src/main.tsx` 返回 200 且已转译为 JSX**；`vite build` 成功转译 **1618 模块**。

⚠️ 顺带发现：**用户那个 5173 的 dev server 是补依赖之前启动的旧进程** → 需要重启，否则报 `Cannot read properties of undefined (reading 'visitors')`。
（**"改了依赖但没重启"是个高频坑**，值得单独记一条。）

### 3. ⭐ 冒烟抓出**两个会让页面白屏**的契约问题

这两个都不是"报错"，而是**安静地崩**，所以值得单列：

| # | 问题 | 为什么危险 | 结论 |
|---|---|---|---|
| 1 | **`GET /api/learning-path` 形状不一致** | 线上返回**对象** `{target_kp_id, steps}`，而 `api-spec` §4.4 与前端类型都要求**顶层数组** → `PathTimeline.tsx` 直接 `for (const step of steps)` 抛 **`steps is not iterable`**；而且 `steps.length` 是 `undefined`，**"加载中/空态/时间线"三个分支全部落空** → **白屏且无提示** | 首选 P2 改后端（合 spec，前端零改动）；前端加兼容层兜底 + 开 Issue #15 请对口收口 |
| 2 | **`capabilities` 字段漂移** | 线上返回 `supported_material_types` / `max_upload_mb` / `parse_methods` / `llm_mode`，与前端假设的不同 | 前端做**双形状兼容**（不白屏），同时报 Issue #15 |

**方法学（今天最值得记的一条）**：

> **"后端返回了 200"不等于"前端能用"。** 真正决定页面生死的是**形状假设**：
> 数组 vs 对象、字段名、可空性。
> **凡前端直接解构/迭代后端数据的地方，都要问一句：如果它是另一种形状，我会白屏吗？**

顺带确认了**符合约定**的部分（避免只记坏的）：非 JSON 响应（`/markdown`、CSV）成功时 **`X-Request-ID` 响应头存在**；400 校验错误带可读中文；QA 全链路（建/查/state/report/删）正常，且 `SessionReportOut` 与前端类型**完全一致**。

- ⚠️ 但**前端还没部署**：线上 `/` 返回的是「析知 XiZhi · 后端已就绪」**占位页**，不是 SPA → **在线六页回归要等 P2 部署**（这条后来成了 D5 的任务）。

### 5. 一个权限事实：`gh auth status` 说未登录，但 `gh auth token` 可用

**结论**：**AI 侧可以只读调用 GitHub API**（PR 状态、Issue、评论），但**合并 PR 这类写操作仍需要人**。
