## 二、我加了第 4 组：**对照**（否则 B1-4 会变成真空满足）

**3 组"矛盾"是不够的。** 因为实现里有一条路径会**无条件**把边标成待复核：

```python
# backend/app/api/review.py（import-edges，第 221 行）
row.needs_review = 1          # 所有导入的候选边一律标待复核
```

```python
# backend/app/graph_view.py（第 113 行）
"conflict_count": sum(1 for e in edges if e.needs_review == 1),
```

**⇒ 如果判据只是"检查这 3 组是否被标为 `needs_review`"，那么"凡候选一律标"的实现也会 **3/3 通过** —— 而它其实什么都没检出。**

所以夹具里必须有**第 4 组 `C0-CONTROL`：语义与章节顺序一致的一条边，期望它 **不被**标为冲突**。
**它一被误报，前面 3/3 就不算数。**

> 这就是团队纪律 #58「模式 B」的应用：**检查必须先被"应该失败"的样例验证过** ——
> 不报 = 这个检查是假的。

## 三、3 组对抗输入的设计（各打一种矛盾形态）

| 组 | 名称 | 矛盾形态 | 为什么它是"真矛盾"而不是"知识本身反直觉" |
|---|---|---|---|
| **C1** | **逆序前置** | B 在教材里排在 A 之后，语义判定却说 **B 是 A 的前置** | 教材的编排顺序**就是**教学顺序（我校 3.3 → 3.3.5 是递进）；说后面的先学，等于说教材排错了 |
| **C2** | **跨章倒挂** | 第 **6** 章的知识点（TCP 拥塞控制）被判为第 **3** 章知识点（交换自学习）的**前置** | 跨度 ≥ 2 章的前置倒挂，在"章—节"骨架下不可能成立 |
| **C3** | **同节互指** | 同一节（5.2.4）内两个知识点**互相**声明对方是前置 | 两条方向相反的边落在同一节 —— **教学上不可能同时成立**（这是"结构-语义冲突"里最容易被人漏掉的一类） |

**三组刻意覆盖三种不同的矛盾形态**，而不是同一形态的三个例子 —— 因为判据若只对"逆序"敏感，跑到 C3 就会静默采纳。

## 四、判据（**四项全满足才算通过**）

```
✔ C1 / C2 / C3 全部 needs_review = true（检出率 100%）
✔ C0-CONTROL     needs_review = false（对照不误报）
```

**只要 C0 被误报，B1-4 一律判"未通过"** —— 哪怕 3/3 都检出了。
（理由：误报说明这个检查没有区分能力，"检出"是碰巧的。）

## 五、⚠️ 顺带登记一条实现与语义不符（供 P2 判断）

**`stats.conflict_count` 现在的实现是「所有 `needs_review=1` 的边数」，但它的名字与文档说的是「结构-语义冲突边数」。**

- 代码：`backend/app/graph_view.py:113` → `sum(1 for e in edges if e.needs_review == 1)`
- 注释/契约：`backend/app/api/graph.py:5` 写的是「`conflict_count`（结构-语义冲突边数）」
- **可观察的后果**：线上实测 `conflict_count = 625`（而全图 `node_count = 629`）——
  它把**每一条待复核的候选边**都算成了"冲突"。这也是我 9/20 报的那条「`conflict_count=631` 异常」的**根因**。

**两种修法（供你选）**：
1. **改实现**：`conflict_count` 只统计**真冲突**（`source_channel='both'` 且方向与结构相反、或显式冲突标记）—— 需要在导入时打一个 `conflict_kind`；
2. **改语义**：把它改名为 `pending_review_count`，另起一个真冲突计数 —— 零算法改动，但要同步 `api-spec` 与前端。

**我倾向 1 的变体**：因为「检出了 N 条冲突」是 B1-4 的**展示口径**，需要一个真冲突计数；
而「还有 N 条待复核」是另一个独立且也有用的数字。**两个都该有，但不能共用一个名字。**

## 六、跑法（9/24 全量跑时用）

```bash
# 1) 把夹具喂给检测逻辑（P1 的 graph_infer 或 P2 的导入通道）

#      ⚠️ 注意：走导入通道时「凡候选一律 needs_review=1」会让 C0 也进队列 →

```

**⚠️ 最后这条是本节最要紧的一句**：
只要 `conflict_count` 仍等于「needs_review 边数」，**B1-4 就无法用它来举证**。
**要么先修 `conflict_count` 的语义（第五节），要么把判据落在新增的 `conflict_kind` 字段上。**
在此之前，3 组夹具跑出来的"全部被标 `needs_review`"**不构成 B1-4 通过的证据**。
