## 二、⚠️ 从手册里挖出来的两条策略（原来漏了）

### ⭐ 1. 可以提前提交、可多次修改 —— 评委只看最后一次

手册 §4.2 原文：

> 参赛者在 **9月16日至 9月26日**期间，**均可提交作品，提交后也可修改**
> （备注：作品可多次提交，**评委只能看到最后一次提交的作品**，
> 学生可看到自己提交的所有作品修改记录）

**这意味着：不用等到 9/26 才交。**

**建议**：**在 9/22–9/23 就提交一版保底**（哪怕 PPT/视频还是初稿），之后继续改、继续提。
理由只有一个：**把"忘了提交 / 最后一刻上传失败"这个风险直接归零。**
反正评委只看最后一次，先交一版**没有任何代价**。

### ⚠️ 2. 代码要求 `.zip/.tar.gz` 格式，不只是 GitHub 链接

手册 §4.2 文件格式：**`PPT（.pptx/.pdf）、视频（.mp4/.mov）、代码（.zip/.tar.gz）`**

而 §4.1 说的是"源代码仓库 GitHub/Gitee 链接"。

→ **两处都满足最稳**：既有 public 仓库链接，也**打一个 `.tar.gz` 一起提交**。
打包脚本已有思路（排除 `.venv` / `.learnbuddy` / `node_modules`，当前约 **2.2 MB**）。
