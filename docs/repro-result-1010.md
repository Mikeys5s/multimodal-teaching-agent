# 决策 1 的试跑结论 · 2026-10-10 22:16

> **做法**：在容器里 cp 一份库 → 清空抽取产物 → 用 P1 修过的代码重跑。
> **线上库全程只读。**

---

## 一、结果

| | 知识点 | 去重后 | **副本率** |
|---|---|---|---|
| **试跑前**（= 线上现状） | **629** | **146** | **76.8%** |
| **试跑后**（P1 的修复） | **213** | **146** | **31.5%** |

**⭐ 而"去重后"两栏一模一样（都是 146）—— 这是最关键的一点。**

**它说明**：
- **内容总量没变** ⇒ **修复没有丢内容**（**没有靠"少抽"来减少副本**）
- **变的只有副本**：**483 → 67**

---

## 二、⭐ 所以那个歧义**有答案了**：**两者都有**

```
· **483 个副本（86%）是抽取 bug 的产物**  ← 重跑能修掉
· **67 个副本（31.5%）是材料的真实重复**  ← 修完还在，说明本来就有
```

**⇒ 我先前说"单靠数据分不出来"是对的** —— 而现在**试跑把它们分开了**。

---

## 三、⭐ 这个结论**改变了推荐**

**原来我以为要在 A（不重跑）和 B（重跑）里选一个。**

**而现在看：两者不矛盾，最优是「重跑 + 保留标注机制」**：

| | 效果 |
|---|---|
| **重跑** | 清掉那 483 个**假的**副本（**根因闭环**） |
| **保留标注机制** | 剩下的 **67 个真重复**照旧**标注**（**我们原来的做法仍然有用**） |
| **⇒ 收益** | **数字干净了（629→213），而"标注"的价值反而更清晰** —— **因为它标注的是真重复，不是 bug 残留** |

**⭐ 而叙事上更漂亮**：
> 「材料里确实有 **67 处**内容是重复的 —— **我们标注了它们、不去重**；
> 而我们早先版本的抽取器**误把 483 处抽成了副本，那个 bug 我们已经修了**。」

**⇒ 这个说法比"462 副本、只标注"更有说服力** —— 因为它**区分了"材料的属性"和"我们曾经的 bug"**。

---

## 四、⚠️ 但重跑有一个**必须先解决的连带问题**

**kp_id 会变** ⇒ **我已经灌的 26 条例题 + 21 条误区会变孤儿**。

**试跑时我把它们一起清空了** —— 所以现在还是老 id。

**⇒ 要重跑并保留例题，得做一次「旧 kp_id → 新 kp_id」的映射。**

**⭐ 而映射是可行的**，因为：
```
· 每条例题/误区都带 source_page + source_quote
· 而 kp 也有 source_block_id
⇒ **用「材料 + 页码 + 原文」做匹配**，能把旧 kp 映射到新 kp（**重复组的老 id → 新的代表 id**）
```

**工时**：我估 **~40 分钟**（写映射脚本 + 验证）。

---

## 五、⚠️ 还有一个**必须先确认的**

**试跑只用了 `run_extract`，它只做了「结构化抽取」**。

**而线上那 629 条里，可能还有别的来源**（比如早先的 pipeline 版本、或别的步骤产出）。

**⇒ 所以"重跑后 213"这个数字，要先确认它**覆盖了原来所有的产出类型** ——
否则我们会**丢掉一些本来有的东西**。

**⭐ 怎么确认**：比"试跑前 146 个不同内容"和"试跑后 146 个不同内容"**是不是同一批**
（如果完全一致，说明没丢；如果少了几个，说明有别的来源）。

**⇒ 这一步我还没做，建议做（~15 分钟）。**

---

## 六、我的推荐（**更新版**）

| 序 | 做什么 | 工时 | 为什么 |
|---|---|---|---|
| **1** | **确认"146 个内容"两批是否一致** | ~15 min | **不做这步就重跑，可能丢东西** |
| **2** | **写「旧 kp_id → 新 kp_id」映射** | ~40 min | 保护已灌的例题/误区 |
| **3** | **在副本库上跑完整流程（含映射）** | ~20 min | 验证一遍 |
| **4** | **确认无误后再动线上** | ~30 min | 备份 + 重跑 + 灌例题 |

**总计约 1.5–2 小时。**

**⚠️ 而离截止只剩 3 天** —— **这 2 小时值不值，取决于你觉得"数字干净 + 叙事区分开"值多少。**

**⇒ 我的看法**：
**如果 P1 那边不紧张，值得做**（因为它把"bug"和"材料属性"分开了，答辩时更硬）。
**如果时间紧，不做也不致命** —— 因为"我们标注重复、不去重"这个说法**本身成立**。
