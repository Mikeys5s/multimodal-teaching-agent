# 学习路径页裸 `kp_id`：三个方案 + 我的推荐

> 2026-10-09 · 美佳问「隐藏，还是换回知识点名字」
> **我的回答：都不是最优。下面是量过数据后的建议。**

---

## 一、先把事实摆清（**都实测过**）

### 1. 后端**已经给了名字**

```jsonc
// GET /api/learning-path?kp_id=…  —— 返回 4 条
[
  { "order": 1,
    "kp_id": "kp_cf6fcaa0_000_000_022",
    "name": "The main problem with FIFO que",   // ← 后端有 name
    "difficulty": 4, "reason": null, "is_start_point": true },
  …
]
```

**⇒ 所以"前端没名字可用"这个假设是错的** —— 名字**已经在响应里**，
只是前端**额外把 `kp_id` 也渲染出来了**。

**⭐ 而这和「答疑页」的问题是同一个形状**：
后端给了名字，前端把 id 一起画了。（**我昨天只修了答疑 SSE，学习路径没动**。）

### 2. ⚠️ 但"名字"本身读不通 —— **这条最要紧**

我把路径上那 4 个点逐个查了：

| kp_id 末段 | **原名（现在显示的）** | 可读标题 |
|---|---|---|
| `_000_000_022` | `The main problem with FIFO que` | **（无）** |
| `_000_000_024` | `What we really want` | **（无）** |
| `_000_000_026` | **`There`** | **（无）** |
| `_000_000_028` | `Because FQ` | **（无）** |

**全库对照**：629 个点里 **438 有可读标题（69.6%）** ——
**而这 4 个正好全在那 191 个"没有"的里面。**

**⇒ 所以"换回知识点名字"这个选项——换过去读的仍然是 `There` 和 `Because FQ`。
问题只解决了一半。**

---

## 二、三个方案，逐条权衡

### 方案 A · **隐藏 `kp_id`**

| 好处 | 代价 |
|---|---|
| 界面立刻干净 | **丢掉"可核查性"** ⚠️ |

**⚠️ 为什么我不推荐**：
你们的答辩主线里有一条是「**三级结构 + 溯源覆盖率 100%**」，
而 **`kp_id` 是"从界面回到材料"的那把钥匙**。
**评委如果问「你这个结论的依据是什么」，界面上没有任何可点的东西，
就只剩口头解释。**

**⇒ 它不该"消失"，只该"不抢戏"。**

---

### 方案 B · **只把 `kp_id` 换成 `name`**

| 好处 | 代价 |
|---|---|
| 改动最小（**前端一个字段**） | **换过去仍是 `There` / `Because FQ`** ⚠️ |

**⇒ 实质是"把读不通的英文 id 换成读不通的英文片段"。**

**⚠️ 而且这里有个细节**：那 4 个名字里有 3 个**首字母大写的英文句片段**
（`What we really want` / `There` / `Because FQ`）——
**它们看起来"像标题"，但语义不完整**。**换成这个，学生还是一头雾水。**

---

### ⭐ 方案 C（**我推荐**）· **名字做主、`kp_id` 降级可查**

**做法（三处小改）**：

```
① 主文案：`name`（**照实显示，不美化**）
   —— 「The main problem with FIFO que」这种**如实呈现**
   —— **不要为了好看去截断或改写**（那会撞"宁缺毋错"）

② 溯源锚：`kp_id` 从"正文一行"降级为**悬浮可点的小标签**
   —— 视觉上不占位（比如放在行尾，灰色小字 `#022` 或一个 🔗 图标）
   —— **鼠标悬停显示完整 kp_id**，点击可复制/跳转
   —— **⇒ 界面干净了，但"可核查"没丢**

③ 序号栏补一个**语义**（**这条最提升体验**）
   —— 现在每步只有「1 2 3 4」，而"这几步为什么按这个顺序"没说出来
   —— 把后端的 `reason` 或"先修 → 后修"的**前置关系**说一句
   —— **⚠️ 注意**：`reason` 在实测里是 `null`（见下），**这条要先确认后端能不能给**
```

**关于 `reason: null`** —— 我实测时它全是 `null`，
**但⚠️截图里"排序依据"那行是有内容的**，说明前端用的是别处的数据
（或我传的参数不对）。**⇒ 这条要跟前端对一下，别只看一个接口就下结论。**

---

## 三、还有一个**更根本**的选项（**方案 D**，我列出来但你定）

### 给那 191 个点**补可读标题**

**现状**：`section_heading` 来源的 282 个可读性高（**来自材料小节标题**），
`raw_name` 来源的 156 + 缺失的 191 = **347 个可以改善**。

**做法**：用**材料原文里该点所在的句子**做标题（**LLM 抽一句 + 人工抽检**）。

| 好处 | 代价 |
|---|---|
| **一处修，全站受益**（学习路径 / 图谱 / 答疑**三处都在用 name**） | **要跑一遍抽取 + 抽检**（我估 **1.5–2 小时**） |
| 解决的是**数据质量**，不是遮 UI | **改的是数据，要重新灌库 + 复验** |

**⚠️ 但我要提醒一个风险**：**离 10/13 只剩 4 天**，
而 P3 还要**录 3 分钟视频**。**⇒ 方案 D 的收益大，但它会挤占别人的时间。**

---

## 四、我的推荐（**按性价比排序**）

| 序 | 做什么 | 工时 | 谁 | 为什么排这个 |
|---|---|---|---|---|
| **1** | **方案 C②③** —— `kp_id` 降级为悬浮小标签 + 序号栏补语义 | **~40 分钟** | **P3**（前端） | **界面立刻干净，且溯源不丢** |
| **2** | **方案 C①** —— 主文案用 `name`（**照实，不美化**） | **10 分钟** | **P3** | 和 1 同一处改 |
| **3** | **⚠️ 先确认 `reason` 为什么是 null** | 15 分钟 | 我或 P3 | **别在错的前提上改 UI** |
| **4（可选）** | **方案 D** —— 给 347 个点补可读标题 | 1.5–2h | **我** | 收益最大，但**可能挤占视频时间**，**建议征得 P3 同意再排** |

---

## 五、我的建议一句话

> **别隐藏，也别只换名字 —— 把 `kp_id` 从"正文"降到"脚注"，然后去修数据（如果时间够）。**

**理由**：`kp_id` 是你们**溯源覆盖率 100%** 这条卖点在界面上的**唯一可见凭据**；
而 `name` 读不通是**数据问题**，**用 UI 遮不住**。
