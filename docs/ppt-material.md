### 1.2 知识点结构化（Stage 2）

| 数字 | 值 | 来源 |
|---|---|---|
| 知识点条目 | **629** | `[knowledge_points.total_entries]` |
| **唯一名字** | **139** | `[knowledge_points.unique_names]` |
| 三级结构完整率 | **100%**（样本 629） | `[quality.acceptance[label=A2-1]]` |
| 溯源覆盖率 | **100%**（样本 629） | `[quality.acceptance[label=A2-3]]` |

**⭐ 这里有个必须讲清的点**（**不讲会被当成问题，讲了是加分**）：

> **629 是"条目数"，139 是"唯一概念数"。**
> 差在**跨节同名** —— 比如 TCP 在第 5 章和第 6 章都出现，各占一条。

**为什么这是对的**：`uq_kp_section_name` 约束要求**同节内**名字唯一，
而**跨节同名是正常的**（不同章节从不同角度讲同一概念）。
代码里那条约束的注释写着理由：

> 同一节里有重名知识点，依赖边就会指向「哪个重名的？」，**无法解释** ——
> 而可解释性是本作品的核心。

**答辩话术**：「我们不是简单去重，而是**按节隔离**：同节必须唯一（否则依赖边无法解释），
跨节允许同名（那是不同视角）。」

### 1.4 答疑（Stage 3）

| 数字 | 值 | 来源 |
|---|---|---|
| 首轮 | **永远是 `probe`（反问）** | `[qa_live.first_turn_type]` |
| 单轮检索命中 | **5 个知识点** | `[qa_live.retrieved_kp_count]` |
| 单轮 SSE 事件 | 6 个 | `[qa_live.event_count]` |
| **SSE seq 起点** | **1001** | `[qa_live.sse_seq_start]` |
| 幻觉率 | **0%**（样本 44） | `[quality.acceptance[label=幻觉率]]` |

**⭐ `seq=1001` 这条有个故事可以讲**（**体现"规格即法律"**）：

> SPEC §5.2 第 3 条要求「`seq` 在一个会话内单调递增，**跨轮次不重置**」。
> 我们**第一版是每轮从 1 开始**的 —— P3 用两轮实验抓到了（第 1 轮 id 1..6、第 2 轮又从 1 开始）。
>
> **根因**：`start_seq = 1` 只在客户端带 `Last-Event-ID` 时才改，
> 而**正常第二轮不带它** → 又回 1。
>
> **修法**：`start_seq = 学生轮序号 × 1000 + 1` ——
> 于是首轮从 **1001** 开始、第二轮从 **1003** 开始，**天然单调且可预测**。

**答辩话术**：「`seq` 不只是个序号 —— 它是**断线续推**的依据。
跨轮重复会让前端恢复到错误的轮次。**这种细节不写测试就只是文档里的一句话。**」

**⭐ 这里有个反例值得讲**（**"我们怎么发现自己的错"**）：

## 2. 技术方案的"取舍表"（可直接做成 PPT 的一页）

> **做 PPT 的人常犯的错**：只讲"用了什么"，不讲"**为什么不用那个更好的**"。
> 而**取舍**才体现判断力。

| 决策 | 选了什么 | **为什么不做那个更"标准"的** |
|---|---|---|
| 后端框架 | **FastAPI** | Stage 1 解析生态在 Python（PDF/OCR/PPTX 全在 Python）—— **换任何别的语言都要重写解析** |
| 数据库 | **SQLite（WAL）** | 单机、单用户、无并发写 —— **上 Postgres 是给自己加运维** |
| 向量检索 | **NumPy 暴力余弦 + FTS5** | 629 个知识点，**暴力算只需毫秒**；引向量库要付出索引构建 + 依赖体积 |
| 异步 | **BackgroundTasks + 任务表** | **不引 Celery/Redis** —— 单机任务量不值得多两个中间件 |
| 图可视化 | **自研纯 SVG + 自研 DAG 分层布局** | 见 §3（**这是 D-01，SPEC 已按此更正**） |
| LLM 调用 | **构建期用平台，运行期零外部依赖** | 赛事要求 LearnBuddy 为唯一平台 —— **我们让关键路径根本不需要 LLM** |
| 音频 | **不做** | 砍掉的理由写在 SPEC §6.1 —— **做窄通道会击穿"幻觉率为 0"的红线** |

**⭐ 最能讲的一条是最后一条**：

> **"我们不是能做的都做了，是知道哪些做了会坏事。"**
> 音频那条：ASR 错识别会让**溯源引用的原文本身就是错的** ——
> 那会**击穿我们的红线**。所以不做，并在 SPEC 里留了决策记录。

## 3. D-01：图可视化（**已拍板，可直接讲**）

| 项 | 内容 |
|---|---|
| **SPEC 原文** | 「图可视化 \| `Cytoscape.js`（DAG）」—— 两处（冻结表 + D6 任务） |
| **实际实现** | **自研纯 SVG 画布 + 自研 DAG 分层布局**，`cytoscape` 依赖不存在 |
| **处置** | **方案 A：改 SPEC 承认自研**（美佳拍板） |
| **理由** | 自研布局能讲「**最长路径分层 + 重心排序压交叉**」，**比"用了某个库"更有技术含量** |

**自研布局的算法（可直接讲）**：

1. **Kahn 拓扑序做最长路径分层** —— 层号 = 所有前置层号最大值 + 1，入度 0 落第 0 层
2. **层内重心排序**（下扫 4 轮 + 上扫 4 轮）压交叉
3. **层 → x**（左→右即先修在前），层内序号 → y

**⭐ 而且我们保留了"发现不一致并记录"的过程**（`docs/spec-diff-log.md`）：

> 那份文件开头写着：
> 「**先记事实与证据，再决定改代码还是改文字。**
> 不允许『反正能跑，就不记了』——
> **评委手里同时有 `SPEC.md` 和代码，文字与实现打架，比实现简单更减分。**」

**答辩话术**：「我们自己做了 SPEC 与实现的差异审计，**发现了一处并走了变更流程**。
这件事本身说明我们的**规格管理是真在跑的**。」

## 4. 主创新点的一句话陈述（**用 SPEC 定稿的那句**）

> **AI 预抽取 + 人工校验的知识点依赖图构建，
> 并首次把「教学依赖图必须无环」作为工程不变量强制保证；
> 据此生成可解释的学习路径与卡点根因回溯。**

**拆成三块讲**：

| 块 | 一句话 | 证据 |
|---|---|---|
| **AI 预抽取 + 人工校验** | 不是"全自动抽取"，是 **AI 干粗活 + 人做裁决** | `/graph` 的**人工复核抽屉**（视频里要演这一步） |
| **无环作为工程不变量** | 写库前校验、违规剪枝 —— **不是希望它无环，是它不可能有环** | `cycle_count = 0`，且有两个独立来源可复算 |
| **可解释的学习路径** | 路径每一步都能说"为什么它在前面" | 依赖边带 `reason`（边理由完备率 100%） |

**⚠️ 表述纪律**（`deliverable-plan.md` §四 定的）：

- **不说"全自动抽取"**，说「**AI 干粗活 + 人做裁决**」
- **不说"我们来自不同专业"**（三人都是人工智能专业，硬说会被查）
- **视频里必须演「人工复核」那一步** —— 那是主创新点的**可点击证据**
