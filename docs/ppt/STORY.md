# STORY · 析知 XiZhi 作品介绍 PPT

> **场合**：粤港澳大湾区 AI Coding 创新大赛 · 方向一「AI + 教学管理助手」初赛评审
> **受众**：评委（技术与产品背景，**会追问数字口径**）
> **页数**：14 页
> **核心任务**：让评委在 3 分钟内相信 —— ①这不是套壳 ②核心创新是工程不变量而非口号 ③**他们自己承认数据有瑕疵**

---

## 一、一句话定位

**析知 = 把一堆教学材料（PDF / 板书照片 / PPTX）变成「可查询、可溯源、能引导自学」的结构化知识体。**

**它和同类产品的分野**：
不是"能问答"，而是**「依赖图必须无环」这件事被当成了工程不变量** ——
**不是我们希望它无环，是它不可能有环。**

---

## 二、叙事主线（**"我们怎么发现自己的错"是暗线**）

### 明线：从材料到知识体的三阶段

```
Stage 1 解析   材料 → 带页码锚点的 Markdown（零外部依赖）
Stage 2 结构化  → 章—节—知识点 + 前置依赖 DAG（**环数必须为 0**）
Stage 3 答疑    → 苏格拉底状态机（**首轮只反问，连错 2 次代码层强制降级**）
```

### 暗线：**每一页关键结论后面，都有一个"我们本可以不说"的细节**

**这条暗线是本次答辩的差异化**：评委见过太多只报喜的项目。

| 页 | 明线内容 | **暗线（主动暴露）** |
|---|---|---|
| 数据页 | 629 条抽取结果 | **它其实是 167 个不同内容 —— 同一份材料被抽了 4 遍，我们没去重** |
| 依赖图页 | 环数 0 | **这 0 是"检查过"的 0**，因为 `pruned_count` / `conflict_count` 一起报出来了 |
| 硬前置页 | 15 条 hard 边 | **其中 1 条我们故意没灌** —— 它与 AI 按文档顺序判的方向相反 |
| 答疑页 | 首轮只反问 | **"连错 2 次强制降级"是代码层兜底，不依赖模型自觉** |

## 四、情绪曲线（**评审注意力管理**）

```
注意力
  ▲
  │  ╭─03 痛点                    ╭─07 数据（暴露）      ╭─12 瑕疵（主动）
  │  │                            │                      │
  │──01 封面──02 目录──04 我们做的──05 主创新点★──06 人裁决──08 答疑──09 路径★──10 取舍──11 质量──13 链接──14 团队
  │                              ╰─ 这里是全篇最高点（工程不变量）
  ▼
```

**⭐ 三处"主动暴露"（07 / 12）是刻意的** —— 它们让 05 的"工程不变量"**从口号变成习惯**。

---

## 五、三条要贯穿全篇的表述纪律

1. **不说"全自动抽取"** → 说「**AI 干粗活 + 人做裁决**」
2. **不说"我们希望它无环"** → 说「**它不可能有环**」（写库前校验）
3. **不说"629 个知识点"** → 说「**629 条候选，其中 167 个不同内容，100% 待人工复核**」

---

## 六、必须规避的（**答辩现场会被问穿**）

| ❌ 不能说 | ✅ 改成 |
|---|---|
| 「我们来自不同专业」（**跨专业加分不满足**） | 只说「三人同属人工智能专业」 |
| 「629 个知识点」 | 「629 条候选 / 167 个不同内容」 |
| 「全自动知识抽取」 | 「AI 预抽取 + 人工校验」 |
| 「基本实现了…」 | 给**可测数字** |
| 把 `conflict_count = 625` 说成"冲突" | 它是**"未经人复核的边"** —— **这个概念要说准** |
