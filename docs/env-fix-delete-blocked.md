# 环境故障处置：删除/改名被拦 → git 无法提交

**记录**：2026-09-19 20:45 起
**影响**：git 的**全部写操作失效**（提交、切分支、写 index）；`sed -i`、`rm`、`mv` 也不可用

---

## 一、故障是什么（先看清楚，别急着重启）

**现象**：任何"删除"或"改名"都被拦下。

```
Python os.remove  →  OSError: [safe-delete][SAFE_DELETE_FAIL_CLOSED]
                    {"reason": "windows-sandbox-recycle-bin-unavailable"}
Python os.rename  →  PermissionError: [WinError 5] 拒绝访问
sed -i            →  sed: cannot rename scripts/sedXXXXXX: Permission denied
```

**为什么会连带 git 挂掉**：

> **git 写 index 走的是「写临时文件 → 改名」**。
> 改名被拦 → **整个写操作失败** → `fatal: unable to write new index file`。
> `sed -i` 也是同一个套路（临时文件 + 改名）。

**所以不是 git 的问题，是"改名"这个动作被拦了。**

**已经排除的**：不是那个 `.git/config.lock` —— **克隆一份全新仓库，同样写不了**。

---

## 二、处置步骤（从轻到重，通常第 1 步就够）

### 第 1 步：检查 WorkBuddy 安全中心的策略 ⭐ 最先试这个

报错里那句 `windows-sandbox-recycle-bin-unavailable` 已经指明了位置 ——
是**应用沙箱自己的回收站**不可用。

1. 打开 **安全中心**
2. 找与 **「文件操作 / 删除 / 回收站」** 相关的条目
3. 看有没有「**文件删除需经回收站**」这类开关 —— 如果有，**关掉它**（或改成直接删除）
4. 顺带看一下 **「系统级工具」** 策略 —— 现在 `reg` / `wsl` / `wmic` 也是被它禁用的（我今天想查注册表就被拦了）

> **为什么这步最可能有用**：安全沙箱的回收站在某些情况下会不可用（权限、容量、路径不合法），
> 而它的设计是**"回收站不可用就 fail closed（拒绝操作）"** ——
> 也就是说**宁可不让删，也不直接删**。这是安全上的正确选择，但在开发时是致命的。

### 第 2 步：重启 WorkBuddy 应用

**完全退出**（不是关窗口 —— 托盘图标也要退），再重新打开。

沙箱层是随应用起来的，重启会让它重新初始化回收站。

### 第 3 步：检查 Windows 回收站本身

- 桌面 → **回收站** → 右键 **属性**
- 看 **D 盘** 那一行（我们的项目在 `D:\muti_tagent`）
- 如果勾着 **「不将文件移到回收站」** → **取消勾选**
- 如果配额是 **0 MB** → 改成 **1 GB 以上**

> 这是 Windows 上最常见的成因：**某个盘被单独设成"删除不进回收站"**，
> 于是任何"移到回收站"的调用都会失败。

### 第 4 步：重启电脑

如果前三步都不行 —— 可能有句柄占着 `$Recycle.Bin`（今天 20:45 那个 `.git/config.lock`
是**突然出现的、962 字节、删不掉**，很像被占用）。**重启能清掉这类句柄。**
