## 0. 为什么必须先做这件事

B1-1 的验收方式是「从抽出的边中随机抽 50 条，人工判定这条前置关系在教学上是否成立，合理率 ≥ 80%」。

**如果三人对"成立"的理解不一致，这个指标就没有意义** —— 同一批边，甲判 90%、乙判 60%，验收结论完全取决于谁来判。所以先花 40 分钟对齐口径，比多判 50 条边重要得多。

---

## 1. 判定口径：三问法

对每条边 `(A → B)`，依次问三个问题。**任一问答"否"即判不成立。**

### 问 1 · 不学 A 能不能学 B？

| 回答 | 结论 |
|---|---|
| 不能，B 的推导里直接用到 A | → **成立 · hard** |
| 能，但会明显吃力或容易走偏 | → **成立 · soft** |
| 完全不影响 | → **不成立**（到此结束，不必再问 2、3） |

### 问 2 · A 与 B 是不是只是"同层并列"？

如果 A 和 B 是**并列的同级机制**、**共同依赖同一个前置**、或**只是同属一节/同章**，那不是前置关系。

> **最重要的区分**：**共享前置 ≠ 互为前置。**
> 例：慢启动与 AIMD 不对称性都建立在"拥塞窗口"之上，但二者彼此**不是**前置关系 —— 它们是从同一个根分出的两个分支。

### 问 3 · 理由能不能落到"B 的哪一步会卡住"？

判定时必须能写出**具体卡在哪一步**。

| 理由形态 | 判定 |
|---|---|
| ✅「不知道 A 是什么，B 里的〔某个具体步骤/公式/术语〕就无从理解」 | 可接受 |
| ❌「二者都属于网络层」「都属于 6.3 节」「都涉及 TCP 拥塞控制」 | **理由不成立 → 判不成立** |
| ❌「掌握 A 有助于理解 B」这类泛泛表述 | **判不成立**（太弱，等于没说） |

**判定输出三档，不是两档**：

| 判定 | 含义 | 处理 |
|---|---|---|
| `成立-hard` / `成立-soft` | 明确成立 | 进 B1-1 分子 |
| `不成立` | 明确不成立 | 进 B1-1 分母，不计分子 |
| `存疑` | 说不清，或三人讨论后仍不一致 | **不计入 B1-1**，转 `needs_review`，并记入下方「边界案例手册」 |

## 2. 十条样本边（先独立判，别翻到 §4）

**操作方式**：三人**各自独立**在下面表格里填判定（不看别人），然后比对。

**填写格式**：`成立-hard` / `成立-soft` / `不成立` / `存疑`

| # | 前置 A | 后置 B | 给出的理由 | P1 | P2 | P3 |
|---|---|---|---|---|---|---|
| 1 | 拥塞窗口 CongestionWindow | 乘性减 Multiplicative Decrease | 不知道「减半」减的是哪个变量、这个变量从哪来，乘性减这条规则就无从落地 | | | |
| 2 | 拥塞窗口 CongestionWindow | 加性增 Additive Increase | 加性增的增量公式分母就是拥塞窗口（MSS/cwnd），不理解 cwnd 的语义与单位就无法理解这个公式为什么能实现线性增长 | | | |
| 3 | 加性增 Additive Increase | AIMD 的不对称性与稳定性 | 「不对称」是加性增与乘性减两半的对比结论，只讲加性增这一半无法成立 | | | |
| 4 | 慢启动 Slow Start | 快速恢复 Fast Recovery | 快速恢复做的事就是「删掉那段慢启动」，不知道慢启动是什么、代价在哪，就无法理解快速恢复优化了什么 | | | |
| 5 | 加性增 Additive Increase | 慢启动 Slow Start | 不构成阻塞，但先理解加性增（线性）再学慢启动（指数），两者对比之下更容易记住慢启动为什么快、以及在什么位置交棒给加性增 | | | |
| 6 | 慢启动 Slow Start | 慢启动为何「慢」 | 这条知识点本身就是对慢启动命名的解释（「慢」是相对一次性发完整个通告窗口而言） | | | |
| 7 | 乘性减 Multiplicative Decrease | 慢启动 Slow Start | 二者都是 TCP 拥塞控制的核心机制，理解乘性减有助于理解慢启动的触发与退出条件 | | | |
| 8 | AIMD 的不对称性与稳定性 | 慢启动 Slow Start | 二者都建立在拥塞窗口之上，理解了 AIMD 的稳定性结论有助于理解慢启动的设计动机 | | | |
| 9 | 拥塞窗口 CongestionWindow | 快速重传 Fast Retransmit | 快速重传后会调整拥塞窗口，所以要先理解拥塞窗口 | | | |
| 10 | 慢启动为何「慢」 | 快速恢复 Fast Recovery | 二者都属于 6.3 节的 TCP 拥塞控制机制，属于同一知识块 | | | |

> 说明：第 1~6 条取自冒烟测试的真实产出，第 7~10 条是**故意构造的**（用于校准"什么不算成立"）。**但我们不告诉你哪条是哪条** —— 独立判完再对照。

## 3. 分歧处理规则（重要）

1. **不一致不等于要投票。** 三人出现分歧时，先各自说出"我认为它是/不是前置，因为……"。**目标是把分歧的点说清楚，而不是少数服从多数。**
2. **讨论后仍不一致** → 判 `存疑`，转 `needs_review`，并**把这条记进 §5 边界案例手册**。后续遇到同类边，按手册里的裁定处理，不再重复讨论。
3. **不许"为了达标而判成立"。** B1-1 是 80% 合理率，本身允许 20% 不合理。**为了让数字好看而放宽口径，等于自己废掉这个指标** —— 而且 PPT 里报一个虚高的数字，被评委追问两条边就露馅。
4. **每条判定必须能引原文。** 判定为"成立"的边，要能指出材料里哪句话支撑这个依赖方向。

|---|---|---|
| 1 | **成立-hard** | 问 1 直接命中：乘性减的规则就是"把 cwnd 设为一半"，不知道 cwnd 无从落地 |
| 2 | **成立-hard** | 问 1 命中，且问 3 能落到具体位置：增量公式的分母 |
| 3 | **成立-hard** | AIMD 的"不对称性"本质是两个速率的对比，缺"加"这一半则结论无法成立 |
| 4 | **成立-hard** | 快速恢复的**定义**就是"移除那段慢启动"，不先理解慢启动则定义读不懂 |
| 5 | **成立-soft** | 问 1 回答"能学但吃力"：慢启动本身可独立理解，但先有线性增长作对比会显著降低认知负担 |
| 6 | **成立-hard** | B 是对 A 命名的解释性知识点，脱离 A 则 B 无所指 |
| 7 | **不成立** | **问 2 命中**：乘性减与慢启动是**并列的两条机制**（一个是超时后的降窗，一个是冷启动的升窗），不是前后置关系。理由里"都是核心机制"属于问 3 的空话 |
| 8 | **不成立** | **问 2 命中**：**共享前置 ≠ 互为前置**。二者都建立在拥塞窗口上，但都是从同一根分出的分支，彼此无依赖 |
| 9 | **不成立（最易误判的一条）** | **把"后续影响"当成了"前置依赖"**。快速重传确实会（间接）影响拥塞窗口，但**理解快速重传本身不需要先懂拥塞窗口** —— 它依赖的是「重复 ACK」这个另一条线上来的概念。判这条时问自己：不学 A，B 的定义/步骤能不能读懂？能 → 不成立 |
| 10 | **不成立** | **问 3 命中**：理由只说了"同属一节"，属于典型的空话理由，不构成教学依赖 |

**期望结果**：1~3 判 `成立-hard`，5 判 `成立-soft`，6 判 `成立-hard`，7~10 判 `不成立`。

**如果三人在某条上不一致，那条就是你们真正的口径缺口** —— 重点讨论它，而不是急着往下判 50 条。

**已预留的待裁定类型（讨论时若遇到，直接补进上表）**

| 类型 | 特征 | 建议裁定方向 |
|---|---|---|
| 反向影响 | A 影响 B 的后续行为，但 B 本身不依赖 A（如样本 #9） | **不成立** |
