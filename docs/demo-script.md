### ⭐ 环节 5 的两套演法（**开录前根据数据状态选一套**）

> **背景（2026-09-21 干跑实测）**：线上 `/api/review/queue` 的 **200 条候选边全部是 `soft`，`hard` 候选边 0 条**；
  全图 `stats.hard_edge_count = 0`。
> 而 **`soft` 边不进入学习路径的先后约束** —— 所以「采纳 → **路径变化**」这个因果**现在演不出来**。
> （已开 Issue #94 请 P2 导入 3–5 条 `hard` 候选边；payload 格式已在 Issue 里给出。）

| | **方案 A（首选）** | **方案 B（降级，零前提）** |
|---|---|---|
| **前提** | 队列里**有 `hard` 候选边**（Issue #94 解决后） | 无需任何前提，**现在就能演** |
| **画面** | 打开复核抽屉 → 挑带「**硬前置**」标签的那条 → 点采纳 → **切到 `/path` 指给镜头看路径变了** | 打开复核抽屉 → 采纳一条（soft）→ 指出**待复核角标减少 + 队列条数减少** |
| **台词** | 「这条边是 AI 在构建期判出来的候选。**但候选不等于结论** —— 所以我们把它送进复核队列。**人工采纳之后，它才进入正式图。** 你注意看这里的顺序变了：**这条依赖现在真实地约束了学生的先后**。这就是『**AI 干粗活 + 人做裁决**』。」 | 「这条边是 AI 判出来的候选，**候选不等于结论** —— 人采纳之后它才进正式图。这里显示的角标减少了，就是『**人做裁决**』的痕迹。<br>另外说明一下：这条是**软前置**，它不约束先后；**如果是硬前置（不会就学不动），学习路径的顺序会随之改变** —— 我们的复核队列会区分这两类。」 |
| **强度** | ⭐⭐⭐ **看得见的因果** | ⭐⭐ **看得见的动作**（但把 hard/soft 的区别讲出来了，反而是一个加分点） |
| **诚实性** | 完全成立 | **完全成立，不撒谎** —— 它明确说了"这条是软前置，所以路径不变" |

**🔴 无论走哪套，都不要说「这里路径变了」而实际没变** —— 镜头会拍到 `/path` 页。
**开录前先跑一次**（30 秒）：`GET /api/review/queue` 看有没有 `relation_type=hard`，有就走 A，没有就走 B。

## 3 风险与兜底（镜头前出问题时的处理）

| 风险 | 现场怎么办 |
|---|---|
| 某页请求失败 / 白屏 | **别停在错页解释**。直接切到下一环节，台词用"这一页的数据这里是…"带过。**兜底：开录前把每页的截图备好，剪辑时替换。** |
| `/tutor` 回答质量差（提问落在噪声知识点上） | **提前用 3–5 个问题试跑一遍**，挑一个回答最稳的写进台词；台词里不要出现"随便问一个" |
| 采纳边之后图**没有明显变化** | 剪辑上做**前后对比**（同一视角录两次），或改成"指 stats 面板里 hard 边数量变化" |
| 录到一半发现超时 | 见 §1 的砍单顺序：**先砍环节 3、再砍环节 6** |
