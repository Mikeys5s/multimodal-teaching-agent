## 一、总体规格

| 项 | 要求 |
|---|---|
| 时长 | **180 秒**（3 分钟，口播 + 操作） |
| 画布 | **1440 × 900**（**必须桌面端全屏，不要缩放**） |
| 浏览器 | **Chrome**（前端按 Chrome 调的） |
| 分辨率 | **1920×1080 录制，输出 1080p** |
| 音频 | **必须有人声讲解**（评委看的是"能不能听懂"，不是"画面多漂亮"） |
| 鼠标 | **放慢、有停顿** —— 快速晃动是新手感最强的信号 |

**⭐ 一条总原则**：**每一段都要"指着屏幕说出一个数字或一条规则"** ——
不要只是"点一下、翻一页"。评委记住的是**数字和规则**，不是你的操作。

## 三、逐段脚本

### 1 · 首页（15 秒）

**[操作]** 打开 `http://120.77.177.171:8000/`，等它加载完（**别边加载边说话**）。

**[口播]**
> 这是**析知**，一个多模态教学智能体。它把讲义和板书，变成**可检索、可溯源、有依赖关系的知识骨架**。
> 首页这三个数字是关键：**213 个知识点、229 条依赖边**，而**依赖图的环数是 0** ——
> 这个 0 是怎么来的，我下面会用图说明。

**[⚠️ 注意]** 等页面**完全渲染**再开口；否则观众会跟着你的鼠标看"转圈"。

---

### 2 · 材料解析（25 秒）

**[操作]** 点左侧「素材」→ 进入 `/materials` → **点一份材料的「预览」**，让 Markdown 出来。

**[口播]**
> 这是解析层。上传的 PDF 和板书照片，本地 OCR 之后**统一转成 Markdown** ——
> 注意每一段都带**页码锚点**，这是后面"可溯源"的前提：**每个知识点都能点回原文那一页。**

**[⚠️ 注意]** **如果这一步加载慢，就先切走再切回来**（别让观众等）。

---

### 3 · ★ 依赖图（40 秒）—— **全片第一重点**

**[操作]**
1. 进 `/graph`，**等画布画完**（**Cytoscape 要几秒**）
2. **指顶部统计条**（停 2 秒，让观众读完）
3. **点画布上任意一个节点** → 右侧「选中节点的证据」滑出
4. **指右侧**「前置依赖」那一段

**[口播]**
> 这是我们的依赖图。**213 个节点、229 条边**，其中 **23 条是硬前置边**。
>
> **[指顶部「依赖环数 0」]**
> 请留意这一项：**依赖环数 = 0**。
> 这个 0 **不是"抽完发现没环"**，而是我们把「**教学依赖图必须无环**」当成一条**工程不变量** ——
> **写库之前先校验，成环的候选边直接剪掉**，不留到运行期。
>
> **[点一个节点，指右侧]**
> 点开任何一个节点，右边给出的是它的**证据**：难度依据、前置依赖、以及**每条前置边带的理由和原文引用**。
> 比如这条 —— 「不学懂 A 就读不通 B」的理由，后面还跟着**教材原文**。
> **所以排序不是黑箱。**

**[⭐ 加分动作（如果时间够）]** 把右侧侧栏**滚一下**，展示"证据很长，能独立滚动"。

---

### 4 · ★ 学习路径（30 秒）

**[操作]** 进 `/path` → 等路径渲染 → **指中间那三步** → **指每一步下面那行理由**。

**[口播]**
> 有了依赖图，就能生成**可解释的学习路径**。
>
> 现在选的目标是「**慢启动的第二种场景**」—— 系统给出**三步**：
> 先看「TCP 的滑动窗口」，再看「两种不同的场景」，最后才到目标。
>
> **每一步都带着理由**，而且**跨章边也有依据** ——
> 比如有一条边，**教材原文自己写了「Recall how TCP's sliding window algorithm works」**，
> 等于材料自己承认这是前置。**这不是我们猜的。**

---

### 5 · ★ 苏格拉底答疑（50 秒）—— **全片第二重点**

**[操作]**
1. 进 `/tutor`
2. **在输入框打一个会超出材料范围的问题**，比如：「**怎么做红烧肉？**」
   → **发出去，让"拒答"出现**（**这一下最能打动人**）
3. 然后**提一个材料里有的问题**（页面上通常有示例问题按钮，**优先点它**）
4. **第 1 轮**发出去 → 拿到**反问**
5. **第 2 轮**随便答一句 → 拿到**提示**
6. **第 3 轮**再答一句 → **拿到直讲**

**[口播]**
> 最后是答疑。这是我们的核心设计：**首轮绝不给答案。**
>
> **[发超纲问题]**
> 先试一个材料里没有的 —— 「怎么做红烧肉」。
> **它明确拒答了**：材料里没有这个内容，我不答、不猜。**我们要求幻觉率为 0。**
>
> **[发正常问题]**
> 换一个材料里有的。第一轮，它**只反问一句**：「先想一个问题，不用急着答对」——
> **这是刻意的**：先看你的起点在哪。
>
> **[第 2 轮]**
> 第二轮给**方向性提示**。
>
> **[第 3 轮 —— 重点]**
> 第三轮 —— 我说了两次没答上来，**它直接讲了**。
> 注意这是**代码层强制**的，**不依赖模型自觉**：**连续两次答不上，就降级直讲。**
>
> 而且每一轮都输出这三样：**涉及知识点、卡在哪一步、下一步练什么。**

**[⚠️ 注意]** 这一段的**节奏**最重要 —— **每一轮之间停 1 秒**，让观众看清状态变化。

## 四、录制技术要点

| 项 | 做法 |
|---|---|
| 录制工具 | **OBS**（免费、能同时录屏 + 麦克风）或系统自带 Game Bar |
| 分辨率 | 1920×1080 · 30fps 足够（**不需要 60fps**） |
| 浏览器 | **Chrome**，**F11 全屏**，**关掉所有其他标签页**（防误触/防露隐私） |
| 缩放 | 浏览器 100%（**别用 125%**，那会让布局变形） |
| 麦克风 | **先试录 10 秒回放** —— 确认没有电流声、回声、键盘声 |
| 鼠标 | **系统设置里把指针调大一点**；或用高亮工具（OBS 有插件） |
| 剪映/剪辑 | **不需要精剪** —— 但**每段之间可以切一下**（观众能感知"换章节了"） |
| 输出 | **MP4 / H.264 / 1080p**，大小控制在 **200 MB 以内** |

**⚠️ 三个最容易翻车的点**：
1. **忘了等页面加载就开口** ⇒ 观众看你鼠标转圈 ⇒ **重开一次**
2. **麦克风电平太高，爆音** ⇒ **先试录回放**
3. **把浏览器其他标签露出来**（有聊天记录/账号信息） ⇒ **开无痕窗口录**

## 五、⭐ 开录前检查（**必做，两处会毁整条录屏**）

```bash
# ① 线上是活的吗
curl -o /dev/null -w "%{http_code}\n" http://120.77.177.171:8000/api/health
#    期望 200

# ② 图谱数据对不对（**录屏里要念的数字**）
curl -s "http://120.77.177.171:8000/api/knowledge-graph?max_nodes=1000" \
  | python -c "import json,sys; s=json.load(sys.stdin)['data']['stats']; \
print('节点', s['node_count'], '边', s['edge_count'], '环数', s['cycle_count'])"
#    期望：节点 213 · 边 229 · 环数 0

# ③ 答疑能不能跑通（**第 5 段全靠它**）
curl -s -X POST http://120.77.177.171:8000/api/qa/sessions \
  -H "Content-Type: application/json" -d '{}' | head -c 200
#    期望：返回一个 session id
```

**⚠️ 两处会毁整条录屏的**：
1. **`cycle_count` 不是 0** ⇒ **停，先别录**，找 P2（我）—— 那说明数据或后端有问题
2. **答疑接口不返回 session** ⇒ 第 5 段（**全片最重要的一段**）没法录

## 六、实际可用的端点（**我实测过的，别改这些名字**）

```
GET  /api/health                                     健康
GET  /api/knowledge-graph?max_nodes=1000             图谱（stats 里含 cycle_count）
GET  /api/knowledge-points?page_size=N               知识点列表
GET  /api/knowledge-points/{kp_id}                   单个知识点详情（含前置边 + 理由）
GET  /api/knowledge-points/{kp_id}/gap-analysis      **卡点根因回溯**
GET  /api/learning-path?kp_id=...                    **学习路径**
POST /api/qa/sessions                                建答疑会话
POST /api/qa/sessions/{session_id}/ask               **多轮答疑（SSE 流式）**
GET  /api/qa/sessions/{session_id}/report            答后小结
GET  /api/review/queue                               复核队列（228 条冲突边）
POST /api/review/decide                              **人工裁决（"人做裁决"的实证）**
GET  /api/report/quality                             质量与验收
GET  /api/materials  ·  /api/materials/{id}/markdown ·  /{id}/blocks
```

**⭐ 其中三个最能打的**（如果时间不够，优先演这三个）：
```
① GET /api/knowledge-graph  →  stats.cycle_count = 0   （工程不变量）
② GET /api/learning-path    →  每步带 reason + 原文     （可解释）
③ POST /api/qa/sessions/{id}/ask ×3  →  反问→提示→直讲  （硬规则）
```
