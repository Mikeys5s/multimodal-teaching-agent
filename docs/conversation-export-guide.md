# LearnBuddy 对话记录 · 导出指引

> 给 P1 / P3 / P2 · 2026-10-07
> 用途：**决赛提交物之一** —— 手册 §5.1「**AI 工具使用 25%**」的评审依据是「**LearnBuddy 使用深度**」

---

## 一、你要交什么（**不用全量**）

**这次要求"每个人"都交**。但**不要求你导出全部逐字对话**（那是你的开发过程）。

**你要交的是 2–3 个具体例子**，每个例子回答三件事：

| 问题 | 举例（**写成你自己的真事**） |
|---|---|
| **① 我让它做了什么？** | 「让它帮我写一个按 mtime 判断索引是否变旧的脚本」 |
| **② 它给的结论是什么？** | 「它建议用 `git diff --cached --stat`，但我实测发现……」 |
| **③ 我改了什么、为什么改？** | 「我换成 `git ls-files | wc -l` 对比 `ls-tree`，因为它的方法在索引变旧时会静默漏报」 |

**⭐ 为什么"我改了什么"最重要** ——
评委要看的是「**你是用 AI 的，还是在被 AI 带**」。
**能说出"它哪里错了、我怎么发现的"，比"它写得多快"有价值得多。**

---

## 二、对话原文在哪（**在你自己的机器上**）

```
~/.learnbuddy/projects/<工作区目录名>/<conversationId>.jsonl
```

**Windows 上是：**
```
C:\Users\<你的用户名>\.learnbuddy\projects\
```

**怎么找：**
```bash
# 列出你所有的会话文件，按大小排
ls -lhS ~/.learnbuddy/projects/*/*.jsonl | head -20
```

**主会话通常是最大的那个**（我们项目 P2 那份是 133 MB / 15136 行）。

## 三、三种导出方式（**按你的需要挑**）

### 方式 A：只要 2–3 个例子（**最省事，推荐**）

**手动摘**：在编辑器里打开 jsonl，**搜关键词**（你记得的问题），
把「**你问的** + **它答的** + **你后来的修正**」三段复制出来，写进一个 `.md`。

**⚠️ 剥离系统注入**：jsonl 里有些是平台注入的块（`<system-reminder>`、`<user_info>` 等），
**那不是你说的话** —— 摘的时候跳过它们。

### 方式 B：用现成脚本导出全量（**P2 写的，可直接用**）

```bash
# 在仓库根目录跑（脚本在 scripts/）
python scripts/export-conversation.py <你的会话.jsonl> exports/my-conversation

# 校验导出完整性（**必跑**）
python scripts/verify-conversation-export.py <你的会话.jsonl> exports/my-conversation
```

**产出**：
```
exports/my-conversation/
  会话记录-完整版.md      ← 按日期分章的逐字对话
  by-date/*.md           ← 按天分册
  index.html             ← 网页浏览版（双击即开）
  raw/conversation.jsonl ← 全量事件（含工具返回值）
```

**⚠️ 两个坑（P2 踩过）**：
1. **先剥 `<system-reminder>` 再抽 `<user_query>`** —— 顺序反了会把注入尾部当成用户消息
2. **脚本要跑在仓库根目录** —— 它按相对路径找 `exports/`

### 方式 C：只要计数（**如果你只想知道自己用了多少**）

```bash
# 数你发过多少条消息
grep -c '"type":"user"' <你的会话.jsonl>
```

## 四、交到哪

**交到仓库的 `exports/` 下，一人一个目录**：

```
exports/
  learnbuddy-conversation/          ← P2（美佳）
  learnbuddy-conversation-p1/       ← P1
  learnbuddy-conversation-p3/       ← P3
```

**⚠️ 别提交到 `main`** —— 按 `CONTRIBUTING.md`：开分支 → PR → 至少 1 人 review。

## 五、⚠️ 提交前自查（**三条**）

| # | 查什么 | 为什么 |
|---|---|---|
| **1** | **有没有泄露密钥** | 对话里可能贴过 token / 密码 —— **搜 `sk-` / `AKID` / `LTAI` / `ghp_`** |
| **2** | **有没有本机绝对路径** | `C:\Users\你的用户名\...` 这种，**评委会看到** —— 能换就换 |
| **3** | **有没有和项目无关的私人内容** | 对话里可能夹着别的事 |

**⚠️ 第 1 条最重要** —— **一次提交就留在远端历史里了。**

| # | 做什么 | 判据 |
|---|---|---|
| **1** | **补齐 + 重导**（现有导出版本只到 **9/26**，要延到 **10/13**） | 时间跨度到 10/13；校验脚本通过 |
| **2** | **⭐ 新增「按主题组织」的索引** | 四章：A 用它做了什么 / **B 哪里刻意不用它** / C 输出被人工改了什么 / D 它帮我们发现了什么 |

**⭐ B 章是我们独家的角度**：手册评「**使用深度**」，
而**"知道哪里不该用"是深度的一种** —— 我们的核心创新（DAG 环路校验 / 学习路径 / 卡点回溯）
**刻意全是纯算法**，**不是"用得少"，是"知道边界在哪"，而且可验证**。

## 七、一句话总结

**交的不是"我们发了多少条消息"，是"我们怎么用它、以及我们改掉了它什么"。**
