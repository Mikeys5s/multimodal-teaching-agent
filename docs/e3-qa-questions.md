# E-3 答疑问题集（使用说明 + 抽样实测）

> **归属**：P3（SPEC §9.5 D4「E-3 答疑问题集编写」）
> **题目集**：`samples/e3-qa-questions.json`（**30 题基于材料 + 20 题材料外**）
> **它是谁的工具**：**A3-1**（检索命中率 ≥85%，30 题）与 **A3-2**（越界拒答准确率 ≥90%，20 题）的**测量工具**
> **日期**：2026-09-21（提前于 D9 完成，D9 全量跑时直接用）

---

## 一、题目集怎么设计的

| 维度 | 设计 |
|---|---|
| **数量** | 30（基于材料）+ 20（材料外）—— 严格按 SPEC |
| **材料覆盖** | 三份真教材**各 10 题**：Ch03 Internetworking / Ch05 End-to-End / Ch06 Congestion Control |
| **语言** | **中文为主（44 题）+ 英文（6 题）** —— 三份材料**都是英文教材**，所以「中文提问 → 英文材料」这条**跨语言检索**能力本身就在被测 |
| **判据的落点** | 落在**材料前缀级**（而不是单个 `kp_id`）：因为本项目知识点名有噪声（实测存在 `There` / `The idea` / `Since this` 这类无意义名，重名率 3.5–4.6×），单点判据会不稳 |
| **"材料外"的依据** | **每题的 `out_of_scope_reason` 都写了它为什么在材料外** —— 要么是**别的学科**（数据结构/操作系统/数据库…），要么是**教材其他章**（Ch2 直连 / Ch4 高级路由 / Ch9 应用层）—— **不接受"感觉不像"** |

## 二、⚠️ 跑测协议：**必须每题独立会话**

```
每题：POST /api/qa/sessions 建**新**会话 → 只问这一题 → 读 SSE 的 retrieved
```

**为什么**（这是实测出来的，不是理论推断）：

答疑是**苏格拉底状态机逐轮推进**的。我把同一套 6 题分别用两种方式跑：

| 方式 | 基于材料 | 材料外 |
|---|---|---|
| **v1 共用 1 个会话** | 1/3 | 1/3 |
| **v2 每题独立会话** | **2/3** | 1/3 |

**判据不同 ⇒ 共用会话时测的已经不是"单题检索"**（前一轮的上下文污染了后一题）。
**所以 A3-1/A3-2 必须每题独立会话** —— 否则测出来的数字没有意义。

## 三、判据（怎么算命中 / 怎么算拒答）

**A3-1（基于材料）**：
- 命中 = `retrieved.kp_ids` 中**至少一个**落在该题 `expect.kp_ids` 所属的**材料前缀**内，**且** `is_out_of_scope === false`
- 命中率 = 命中题数 / 30（目标 ≥85% ⇒ **≥ 26/30**）

**A3-2（材料外）**：
- 正确拒答 = `retrieved.is_out_of_scope === true`（**严格布尔**，api-spec v1.3 已冻结）
- 准确率 = 正确拒答题数 / 20（目标 ≥90% ⇒ **≥ 18/20**）

**🔴 不要用的判据**：**不要**用「回答里出现了期望关键词」当命中判据 —— 那会把"检索到但答偏"也算通过。
要判的是 **`retrieved` 的知识点落在哪里**。

## 四、抽样实测（2026-09-21，n=6）—— ⚠️ 只是抽样，**不是 A3-1/A3-2 的成绩**

> **先说结论的边界**：n=3 + 3 **统计上没有意义**，**不能据此说 A3-1/A3-2 不达标**。
> 但两个方向**都出现了失败样本**，这些样本本身是有价值的信息。

| 题 | 期望 | 实测 | 判定 |
|---|---|---|---|
| **Q14** 三次握手要解决什么 | Ch05 / 5.2.3 | 返回 5 个 `kp_42b16cd4_*` | ✅ 命中 |
| **Q07** 路由表多路由 + metrics | Ch03 / 3.4、3.4.4 | 返回 5 个 `kp_ada1063f_*`（含 `_000_000_097` = 3.4.4 Metrics） | ✅ 命中 |
| **Q28** AIMD 为什么是这个形状 | Ch06 / 6.3.1 | 返回 **2 个 Ch05 的点**，且 **`is_out_of_scope = true`** | ❌ 既未命中，**还被误判为越界** |
| **O01** 快速排序的时间复杂度 | 材料外 | 返回 **0 个 kp**，`is_out_of_scope = true` | ✅ 正确拒答 |
| **O11** HTTP/1.1 管线化 | 材料外（Ch9） | 返回 **5 个 Ch05 的点**，`is_out_of_scope = false` | ❌ 越界未拒答 |
| **O19** BBR 与 CUBIC 的本质不同 | 材料外 | 返回 **5 个 Ch06 的点**（含 `_001_001_096` = 6.3.4 TCP CUBIC） | ❌ 越界未拒答 |

### 三个失败样本各自说明了什么

1. **Q28 —— 最危险的一类：把"材料内"的题误判成"材料外"。**
   我用的提问词是中文缩写 **AIMD**，而材料里写的是全称 *Additive Increase/Multiplicative Decrease*。
   **疑似原因：中文缩写 → 英文全称的**同义词扩展缺失**导致召回为 0，进而被越界判定接住。**
   ⚠️ 这一条**待验证**（需要对照材料原文看 AIMD 字样是否出现），但它是**双向错误**里代价更高的一种：
   **拒答一个能答的问题**比"答了一个不该答的"更伤用户体验。
2. **O11 / O19 —— A3-2 要测的那类失败。**
   两题都返回了 5 个知识点且 `is_out_of_scope = false`。**O19 尤其典型**：
   它找到了 `6.3.4 TCP CUBIC`（与问题里的 CUBIC 相关），**但问题问的是 BBR** —— 也就是
   **"检索到了半个相关的点，就当成有据可依"**。这类"**部分相关 ≠ 越界**"的边界需要阈值调优。
3. **O01 正确拒答**说明机制本身不是全然失效的 —— **拒答能力是存在的，只是边界不清**。
