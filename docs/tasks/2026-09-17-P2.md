### ★ 任务 2 · 后端项目骨架（约 1.5 小时）

```
backend/
├── pyproject.toml          # 或 requirements.txt
├── alembic.ini
├── alembic/
│   ├── env.py
│   └── versions/
└── app/
    ├── __init__.py
    ├── main.py             # FastAPI 实例 + 路由挂载
    ├── config.py           # pydantic-settings 读 .env
    ├── db.py               # engine + session + SQLite WAL pragma
    ├── models/             # ← 任务 3
    ├── schemas/            # ← 任务 5
    ├── api/                # ← 任务 5
    └── ...
```

**依赖清单**（先装最小集，别一口气全装）：

```
fastapi
uvicorn[standard]
sqlalchemy>=2.0
alembic
pydantic-settings
python-multipart
httpx          # 测试用
pytest
```

**关键点**：`db.py` 里必须开 SQLite 的三个 pragma —— `journal_mode=WAL`、`foreign_keys=ON`、`busy_timeout`。**`foreign_keys=ON` 特别容易漏**，漏了外键约束形同虚设，后面数据脏了很难查。

**交付物**：`uvicorn app.main:app --reload` 能起来，访问 `/` 返回 200
**验收**：本地起服务无报错

**验收（逐项勾）**：

- [ ] 14 张表都在
- [ ] **索引都在**（`idx_kp_section`、`idx_blocks_material_seq` 等）
- [ ] **CHECK 约束都在**（`difficulty BETWEEN 1 AND 5`、`relation_type IN (...)`）
- [ ] **外键都在**（用 `PRAGMA foreign_key_list(knowledge_points)` 验）

> ⚠️ **autogenerate 不会生成全部 CHECK 约束与部分索引**，一定要手工核对，必要时在迁移里手写。**这是 SQLite + Alembic 最常见的坑。**
